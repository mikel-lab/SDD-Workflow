# Execution and compatible practices
Main implements and verifies by default after current planning eligibility. No Simple/Main implementation routing, fixed model/effort ladder, mandatory writer or per-task review. Main may delegate bounded independent work only when useful and must maintain complete exclusive ownership including itself.

## Bounded execution
Implement the smallest coherent change satisfying criteria/tasks. Preserve concurrent/user changes; never reset/revert unrelated work. Stop affected writing for material ambiguity, incomplete dependencies, changed risk or paths outside ownership; Main resolves internally where possible. Do not commit/push/merge/deploy/install globally without applicable authority. Normal coherent batches use implementation verification until final review; optional intermediate review needs a concrete question and blocks its dependent scope until resolved.

Run focused tests/builds/inspection and record exact commands, exit/output, criteria and checked baseline/snapshot. Broadening/repeating checks needs new changes/failure/concern, not ritual. Test/build output must be within owned or temporary outputs, never silently alter source or frozen planning. Product/state versions and ignored dependency coverage must reflect actual inputs.

## Superpowers: conditional execution skills
Read each applicable installed skill completely before first use:
- test-driven-development for meaningful feature/bug regressions: observe failing test, implement, observe passing checks.
- systematic-debugging before proposed fixes after unexpected failures.
- receiving-code-review to verify each finding before bounded correction.
- verification-before-completion before any success claim, commit or final report.
- using-git-worktrees when isolation is required; honor existing suitable isolated checkout/runtime support.
- executing-plans for inline practices when compatible; retain official SpecKit tasks and operational evidence, no duplicate plan or cleanup of SDD evidence.
- dispatching-parallel-agents only for Main-authorized independent bounded work; no recursive dispatch.

SpecKit generates official planning; SDD owns lifecycle/gates/scope and user authority. Do not invoke brainstorming/writing-plans as a second active-cycle planning workflow or make subagent-driven-development mandatory. Conflicting self-review fallback, fixed role/model, per-task reviewers, extra approval, one-fix-only shortcut or destructive workspace cleanup cannot override SDD. Existing user authorization takes precedence over routine confirmation defaults. Required independent Reviewer cannot be replaced by author's self-review.

## Corrections
Main verifies feedback, corrects confirmed scope, obtains fresh appropriate evidence and returns to the same Reviewer. A final-review correction returns to final review after verification, without an extra intermediate gate. Planning changes require revalidation/risk assessment and planning review only if triggered. Return Implementation Evidence with changed paths, criterion behavior, checks/version coverage, historical_reads, blockers and residual risk.
